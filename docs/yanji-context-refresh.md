# API 聊天：同一会话整理上下文

2026-09-22 技术记录与使用说明。

言叽普通 API 聊天在未整理历史达到 40 个用户轮次或估算 30,000 文本 tokens 后，于发送时提示「整理一下上下文，接着聊？」。不适用于 Crossing Agent。选「整理后继续」会合并接续笔记，保留至少最近 12 条消息（边界回退到完整用户轮次）；会话标题、ID、模型和完整历史保留。记录中显示最新整理分隔线，无额外常驻按钮。

选择「暂时不要」后，至少增加 10 轮或估算 10,000 tokens 才再次提示。原设置中的上下文限制仍作为自动整理触发条件保留。估算仅计消息文本，不能代表最终输入总量、图片、工具定义或实际账单；整理也会消耗轻模型调用，摘要存在细节损失。

接续笔记和 compactedThrough 游标通过同一次 store 更新落盘。每轮发送从成功整理的游标后开始，解决之前只写摘要、仍按大窗口发送近期原文的问题。缺少摘要或游标无法定位时保留原文。缺失游标的旧版笔记需重建边界，不直接认领未处理历史。

待整理正文每批至多 10,000 字符，长消息继续分片处理，移除旧逻辑单条 800 字和整批 12,000 字的静默截断。每批摘要必须通过结构与长度校验，所有批次成功才提交游标；失败保留旧摘要及原上下文。编辑、删除或截断已整理历史会使摘要失效，版本校验阻止过期结果覆盖新历史。

验证：34 个 Node 测试文件通过；浏览器 store 回归验证会话标题、全部消息保留、游标生效、编辑失效以及过期提交拒绝；Vite 构建成功。测试使用隔离浏览器与虚构消息，不调用真实模型或生产数据。
